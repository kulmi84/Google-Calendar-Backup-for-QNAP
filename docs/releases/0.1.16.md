## Google Calendar Backup 0.1.16

Release candidate for QNAP QTS on x86_64. This release is prepared as a draft; public release and stable status remain pending NAS testing.

### Changes since 0.1.15

- Preserve the existing calendar backup application behavior.
- Include the bundled Node.js runtime's complete license and third-party notices; fail packaging when the runtime license is missing.
- Clarify features, QTS requirements, manual installation, scheduling and restore limitations.
- Correct security documentation to match the QTS login and current configuration path.
- Supply a SHA-256 checksum file and detailed release notes.

### Download and installation

Requires QTS 5.1.0+ on x86_64. Download **GoogleCalendarBackup_0.1.16_x86_64.qpkg** from this release's assets. The adjacent **.qpkg.sha256** file is its SHA-256 checksum.

Open **QNAP App Center → Manuell installieren / Install Manually**, select the QPKG and confirm installation. GitHub source ZIP/TAR archives are not installers.

Launch the application from QTS. Upgrades retain configuration under `/etc/config/GoogleCalendarBackup`. Check the calendars and target folder, run **Jetzt sichern**, and inspect the generated ICS files.

The package is not digitally signed by QNAP. If QTS blocks unsigned packages, review the relevant App Center setting for this deliberately downloaded community package.

### Verification and remaining checks

The build runs all application tests, checks the downloaded runtime's SHA-256, builds with QDK 2.5.3 and verifies required QPKG payload and license files. Inspect the linked GitHub Actions run for the actual result.

Before public publication, record the NAS model, exact QTS version and upgrade source version; test fresh installation and upgrade, configuration preservation, folder selection, manual and scheduled backup, retention, restart, and importing a snapshot into a separate test calendar.

Upgrade test baseline confirmed by the user: 0.1.15 on QTS 5.2.10.3577 with AMD Ryzen Embedded V1500B. Results for the new package are still pending.

### Known limitations

- ARM and QuTS hero are unverified.
- Scheduling uses NAS local time and does not catch up missed runs.
- Folder selection cannot filter by the signed-in QTS user's individual share permissions. Restrict app access to trusted users and protect the backup folder.
- ICS snapshots do not include account settings or sharing permissions; automatic restore is not provided.
