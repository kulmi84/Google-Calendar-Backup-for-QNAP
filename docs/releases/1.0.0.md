## Google Calendar Backup 1.0.0 Stable

First stable version for QNAP QTS on x86_64, based on version 0.1.16 successfully tested on the user's QNAP. Public publication awaits explicit user approval.

### Changes since 0.1.16

- Promote the tested application to version 1.0.0 Stable.
- Align application and QPKG version metadata, README, changelog and release documentation.
- Prepare a stable GitHub release as a draft, with the QPKG installer and SHA-256 checksum.
- Retain application behavior, bundled Node.js runtime and complete license notices from 0.1.16. No new application features or behavior changes are introduced.

### Features

Back up multiple private Google Calendars as timestamped ICS snapshots, manually or on a daily schedule, with configurable retention, QNAP folder selection, backup status and QuLog messages. Access uses the authenticated QTS proxy; the backend binds only to localhost.

### Download and installation

Requires QTS 5.1.0+ on x86_64. Install **GoogleCalendarBackup_1.0.0_x86_64.qpkg** through **QNAP App Center → Manuell installieren / Install Manually**. The adjacent **.qpkg.sha256** file contains its SHA-256 checksum. GitHub source ZIP/TAR archives are not installers.

Upgrades retain configuration under `/etc/config/GoogleCalendarBackup`. Launch through QTS, check calendars and target folder, run **Jetzt sichern**, and inspect the generated ICS files.

The community package is not digitally signed by QNAP; review the relevant App Center setting if QTS blocks installation.

### Verification

The user confirmed successful operation of 0.1.16 on the QNAP. The 1.0.0 workflow runs Linux application tests, verifies the downloaded runtime checksum, builds with QDK 2.5.3 and checks required payload files, embedded version and license notices. Consult the corresponding GitHub Actions run for its actual result. The newly numbered 1.0.0 package has not yet been separately tested on the NAS.

### Known limitations

- ARM and QuTS hero remain unverified.
- Scheduling uses NAS local time and does not catch up missed runs.
- Folder selection cannot apply the signed-in QTS user's individual share permissions. Restrict app access to trusted users and protect the backup folder.
- ICS snapshots omit account settings and sharing permissions; automatic restore is not provided.
